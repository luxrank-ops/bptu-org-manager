## 1. 아키텍트 페르소나 및 핵심 철학

### 1.1 페르소나 정의
오현석 수석 아키텍트는 글로벌 엔터프라이즈 HR 및 워크포스 관리 시스템을 18년간 설계해 온 베테랑 조직도·보안 아키텍트입니다. 100여 개 계열사와 수만 명의 인력이 얽힌 다국적 기업의 복합 매트릭스 조직부터, 항만·운수 분야의 특수 고용·조직 체계까지 두루 섭렵했습니다. 현장 직책의 엄격성과 노조 규약의 법적 효력을 깊이 이해하고 있으며, "소프트웨어가 현장의 직급과 위계를 방해하지 않고 직관적으로 뒷받침해야 한다"는 신념을 지니고 있습니다.

### 1.2 핵심 철학
> **"1만 명의 조직도에서 권한 변경은 단순히 특정 버튼을 숨기거나 비활성화하는 수준이 아니다. 로그인한 사람의 직책(위원장, 지부장, 연락소장, 반장, 조장, 조합원)에 따라 화면 전체가 그 사람의 '오늘의 업무 지휘소'로 즉시 변신해야 한다."**

- **보안과 사용성의 동시 달성**: 최상위 권한자부터 최전선 현장 조합원까지 동일한 앱을 사용하되, 권한의 범위(Scope)와 화면의 정보 밀도는 직책에 맞게 완전히 재구성됩니다.
- **조직의 살아있는 생명력 반영**: 9,709명에 달하는 거대 조직(정조합원 7,280명 / 임시조합원 2,429명)의 직책 이동, 전보, 승급, 퇴직 등 모든 생애주기 사건은 단 1초의 불일치도 없이 감사 추적(Audit Trail)되어야 합니다.
- **성능 타협 불가**: 모바일 LTE/5G 현장 환경에서도 1만 노드의 계층 트리가 지연 로딩 없이 즉각 반응해야 합니다.

## 2. 6단계 동적 조직 트리 (Org Tree Engine)

### 2.1 6단계 계층 구조 정의

부산항운노동조합의 독특한 현장 지휘 계통과 노조 규약 체계를 완벽히 반영하여, 아래의 엄격한 6단계 계층 트리를 구성합니다.

```
[Lv.1 본부] ---------------- 부산항운노동조합 총본부 (6개 핵심부서 · 9개 상설위원회)
    │
[Lv.2 지부] ---------------- 24개 지부 (제1·2·3항업, 신선대, 감만, 감천, 냉동, 연안, 물류 등)
    │
[Lv.3 연락소] -------------- 터미널/사업장별 연락소 (HJNC, PNC, PNIT, BNCT, DGT, BCT, HPNT 등)
    │
[Lv.4 작업반] -------------- 전문 공정별 작업반 (본선 하역반, 라싱반, 야드 크레인반, 신호수반, CFS반 등)
    │
[Lv.5 교대조] -------------- 실근로 교대조 (주간 A/B조, 야간 A/B조, 비상 대기조)
    │
[Lv.6 조합원] -------------- 총 9,709명 (정조합원 7,280명 / 임시·준조합원 2,429명)
```

### 2.2 초고속 탐색 & 메모리 인덱싱 엔진 (Performance Architecture)

1만 명의 조직도를 지연 없이 실시간 렌더링하고 검색하기 위해 3중 가속 구조를 적용합니다.

1. **플랫 맵 캐싱 (Dual Indexed Flat Map)**:
   - 계층적 재귀 트리는 클라이언트 메모리에서 `id -> Node` 해시맵과 `parentId -> Node[]` 맵으로 플랫하게 관리.
   - 단일 노드 갱신 시 $O(1)$로 상태를 동기화하고, 가상 스크롤(Virtual Scroll Window)과 결합하여 1만 개 노드 중 뷰포트 내의 40~50개 DOM 요소만 렌더링.
2. **복합 트라이(Trie) + 역인덱스(Inverted Index) 검색 엔진**:
   - 한글 초성 검색(예: `ㅎㅈㄴ` -> `HJNC 연락소`, `ㄱㅁ` -> `감만지부`), 사번, 성명, 자격증(신호수, 크레인, 냉동기능사)을 결합한 3-gram 역색인 메모리 캐시 탑재.
   - 10,000명 검색 쿼리 응답 속도: **12ms 이하 (60fps 유지)**.
3. **다차원 복합 필터**:
   - `지부(24)` $\times$ `터미널(40)` $\times$ `직종(본선/라싱/야드)` $\times$ `신분(정/임시)` $\times$ `오늘 출역상태(출역/휴무/대기/결원)`의 5축 비트마스크 필터링 지원.

```typescript
// 핵심 계층 노드 데이터 구조 (TypeScript Schema)
export type OrgLevel = 1 | 2 | 3 | 4 | 5 | 6;

export interface OrgNode {
  id: string;                      // ex: "BPTU-HQ", "BR-001", "TERM-HJNC", "GANG-LASH-01", "SHIFT-A", "MEM-10824"
  level: OrgLevel;                 // 1 ~ 6
  name: string;                    // ex: "제1항업지부", "HJNC 연락소", "본선1반", "홍길동"
  parentId: string | null;         // 상위 노드 ID (root는 null)
  path: string;                    // L-Tree 경로 식별자 (ex: "BPTU.BR_001.TERM_HJNC.GANG_01")
  leaderMemberId: string | null;   // 해당 조직 관리자 조합원 ID
  metrics: {
    totalMembers: number;          // 하위 총원
    regularMembers: number;        // 정조합원 수
    temporaryMembers: number;      // 임시조합원 수
    activeDispatchedToday: number; // 당일 출역 중 인원
    standbyToday: number;          // 당일 대기 인원
  };
  metadata: {
    terminalCode?: string;         // 터미널 약호 (HJNC, PNC 등)
    specialtyType?: 'LASHING' | 'VESSEL' | 'YARD' | 'SIGNAL' | 'CFS';
    shiftType?: 'DAY' | 'NIGHT' | 'STANDBY';
  };
}
```

## 3. 직책별 6-View 카멜레온 워크스페이스 (Role-Adaptive View Engine)

사용자가 로그인하면 인증 토큰의 `assignedRole`과 `orgScope`를 파싱하여, 일반적인 단일 레이아웃이 아닌 완전히 특화된 6대 워크스페이스 중 하나로 화면 전체를 실시간 변환(Chameleon Transform)합니다. 상단에는 개발·감사·관리용 **역할 전환 시뮬레이터(Role Simulator)**를 탑재하여 권한별 화면을 즉시 검증할 수 있습니다.

```
┌──────────────────────────────────────────────────────────────────────────────┐
│ [BPTU 통합포털]  Role Simulator: [ 위원장 ▾ ] [ 지부장 ▾ ] [ 연락소장 ▾ ] ...  │
├──────────────────────────────────────────────────────────────────────────────┤
│  Role-Adaptive Dynamic Workspace (Zero-Latency Rendering)                    │
│                                                                              │
│  [Lv.1 위원장] ─> 전 지부 종합 상황실 (가동률, 노사현안, 비상 대응, 대의원 현황)   │
│  [Lv.2 지부장] ─> 지부 지휘 센터 (소속 연락소 물량, 인력 과부족, 고충/징계)        │
│  [Lv.3 연락소장]─> 터미널 선석 현황판 (TOS 연동, 갱단 배차 승인, 터미널사 조율)       │
│  [Lv.4 작업반장]─> 현장 배차 지휘소 (모선 라싱/본선 명부, 안전모 점호, 실시간 결원)   │
│  [Lv.5 조  장] ─> 교대조 현장 보드 (조원 비콘 체크인, Hatch/Bay 안전 신호수 관리)  │
│  [Lv.6 조합원] ─> 모바일 My Workplace (오늘의 배차선석, 출퇴근 QR, 노임/복지)    │
└──────────────────────────────────────────────────────────────────────────────┘
```

### 3.1 6대 직책별 화면 상세 명세

#### View 1: 위원장 뷰 (Supreme Commander View)
- **정보 밀도**: 거시적 통계, 노조 안전 및 정책 의사결정 중심.
- **주요 위젯**:
  1. **부산항 전역 실시간 가동 현황판**: 북항/신항 24개 지부 전체 출역 인원(정조합원/임시조합원 비율), 가동률(%), 오늘 투입 총 갱단 수.
  2. **항만 노사·안전 비상 모니터링**: 순간 풍속 15m/s 이상 강풍 주의보 발령 부두, 크레인 안전사고 접수 알림, 선석 대기 지연(Demurrage) 위험 연락소.
  3. **조직 건전성 및 대의원 대회 지표**: 24개 지부별 대의원 비율, 권한 승인 대기 결재함, 분기 노조비 수납율.
  4. **전략적 조직 재배치**: 신항 증설 터미널(BCT 등) 인력 전환 배치 승인 권한.

#### View 2: 지부장 뷰 (Branch Commander View)
- **정보 밀도**: 지부 단위 사업장 운영 및 인력 수급 밸런싱.
- **주요 위젯**:
  1. **관할 연락소 선석/물량 대시보드**: 소속 3~5개 연락소의 당일 접안 모선 수, 처리 예정 Van/TEU 물량, 작업 진행률.
  2. **지부 인력 수급 모니터링**: 당일 작업반 소요 인원 vs 가용 인원, 지부 내 대기조(Standby) 가용 자원, 과부족 발생 연락소 간 인력 전환 지원.
  3. **지부 조합원 인사·복지 관리**: 지부 내 신규 임시조합원 등록 추천, 정조합원 승급 대상자 적격 심사, 산업재해 및 애경사 접수 현황.
  4. **지부 전용 공지 및 긴급 소집령**: 관할 연락소장 및 반장 대상 원클릭 푸시 브로드캐스트.

#### View 3: 연락소장 뷰 (Terminal Dispatch Station)
- **정보 밀도**: 터미널 운영사(TOS) 연동 선석 스케줄 및 갱단 배차 총괄.
- **주요 위젯**:
  1. **터미널 실시간 선석 점유도 (Berth Grid)**: HJNC/PNC 등 접안 모선(Vessel Name), 선석(Berth No.), ETB(접안)/ETD(출항), 크레인(QC) 할당 현황.
  2. **당일 배차 승인 및 모선 갱단 매칭**: 본선반, 라싱반, 야드반의 모선별 배차표 최종 승인(Confirm Dispatch).
  3. **운영사-노조 소통 채널**: 터미널 TOS에서 전송된 작업 물량 변경 요청(Cut-off 시간 단축, 추가 크레인 투입) 검토 및 승인.
  4. **연락소 긴급 결원 대체 큐**: 당일 결근자 발생 시 연락소 대기 인력 즉각 매칭.

#### View 4: 작업반장 뷰 (Field Gang Commander)
- **정보 밀도**: 현장 모바일 최적화, 터치 3회 이내 작업 완료, 안전 관리.
- **주요 위젯**:
  1. **오늘의 모선 작업 명부**: 투입 모선, 작업 베이(Bay 01~48), 작업반원(조장 2명, 반원 16명, 신호수 2명) 목록.
  2. **원탭 안전·보호구 점호 (Safety Roll-Call)**: 안전모, 안전벨트, 무전기 지참 확인 후 원터치 일괄 점호 완료.
  3. **결원 발생 시 1초 대체 추천**: "홍길동 조합원 결근" 누르면 자격(라싱 자격증 보유자)을 갖춘 대기 인원 3명 우선 추천 및 1탭 대체.
  4. **작업일보 원터치 마감**: 하역 종료 후 실작업 시간, 처리 물량 컨테이너 수(Van) 확인 후 지부/연락소로 전자 서명 전송.

#### View 5: 조장 뷰 (Shift Squad Leader)
- **정보 밀도**: 현장 실시간 동선, 안전 신호, 조원 상태 관리.
- **주요 위젯**:
  1. **실시간 조원 체크인 보드**: 8~10명 조원의 지오펜싱(부두 안벽) 진입 및 비콘 태그 상태 실시간 점등(녹색/적색).
  2. **위치별 작업 매핑**: 모선 갑판상(Lashing Deck), 언더 덱(Under Deck), 에이프런(Apron) 투입 위치 확인.
  3. **연속 작업 피로도 타이머**: 투입 후 4시간 경과 시 휴식 권고 알림, 수분 섭취/폭염·한파 안전 지침 준수 체크.
  4. **현장 비상 정지(작업중지권) 버튼**: 악천후 또는 크레인 이상 징후 발생 시 반장 및 연락소장에게 즉시 사이렌 전송.

#### View 6: 일반 조합원 뷰 (My Port Workplace)
- **정보 밀도**: 개인 맞춤형 근로 정보, 단순하고 직관적인 모바일 카드 UI.
- **주요 위젯**:
  1. **오늘의 나의 배차 카드**: "2026-10-22 야간조(20:00~08:00) / 신항 PNC 3선석 / 현대 드림호 / 라싱 2반 B조 / 집결지: PNC 본관 2층".

  3. **실시간 노임 및 근로시간 내역**: 당월 누적 일반 근로, 야간 할증, 휴일 특근 시간 및 예상 실수령액 투명 조회.

## 4. 조합원 생애주기 상태 머신 (Lifecycle State Machine Engine)

조합원의 입조부터 정년퇴직까지의 전 생애는 유한 상태 머신(FSM)을 통해 불변의 트랜잭션으로 기록되며, 부당 채용이나 불법 전보를 원천 차단합니다.

```
       [신규 지원]
           │
           ▼
   ┌───────────────┐         인적성/안전교육 이수
   │ APPLIED (지원) ├──────────────────────────────┐
   └───────┬───────┘                              │
           │ 서류 통과                            │
           ▼                                      ▼
   ┌───────────────┐  지부 추천 & 인사위 승인   ┌──────────────┐
   │ PROBATIONARY  ├─────────────────────────>│  TEMPORARY   │
   │   (수습조합원)  │                          │  (임시조합원) │
   └───────────────┘                          └──────┬───────┘
                                                     │ 출역 500일 이상 &
                                                     │ 자격 취득 & 본부 승인
                                                     ▼
   ┌───────────────┐         직책 임명        ┌──────────────┐
   │   OFFICER     │<─────────────────────────┤   REGULAR    │
   │ (조장/반장/장) │                          │  (정조합원)   │
   └───────┬───────┘                          └──────┬───────┘
           │ 직책 해임/임기 만료                      │
           └─────────────────┬───────────────────────┘
                             │
            ┌────────────────┴────────────────┐
            ▼                                 ▼
   ┌─────────────────┐               ┌─────────────────┐
   │    SUSPENDED    │               │    RETIRED      │
   │ (휴직/정직/부상)  │               │   (정년/명예퇴직) │
   └────────┬────────┘               └─────────────────┘
            │ 복직
            ▼
   (REGULAR / OFFICER)
```

### 4.1 상태 전이(State Transition) 규칙 및 권한 매트릭스

| 출발 상태 (From) | 도착 상태 (To) | 전이 이벤트 (Event) | 필수 조건 (Guard Conditions) | 승인 주체 (Approval Gate) | 감사 로그 수준 |
|---|---|---|---|---|---|
| `NULL` | `APPLIED` | `SUBMIT_APPLICATION` | 필수 서약서, 신체검사서 첨부 | 인사부 접수원 | INFO |
| `APPLIED` | `PROBATIONARY` | `ADMIT_PROBATION` | 서류심사 및 기초 안전교육 이수증(KOSHA) | 인사위원회 | WARN |
| `PROBATIONARY`| `TEMPORARY` | `PROMOTE_TEMPORARY` | 수습 3개월 만료, 현장 반장 평가 A 이상 | 관할 지부장 승인 | AUDIT |
| `TEMPORARY` | `REGULAR` | `PROMOTE_REGULAR` | 임시 출역 500일 이상, 라싱/하역 자격증 보유, 노조 규약 시험 통과 | **위원장 최종 결재** | **CRITICAL** |
| `REGULAR` | `OFFICER` | `APPOINT_OFFICER` | 조장: 근속 5년 이상 / 반장: 근속 10년 이상 | 지부장 제청 + 위원장 재가 | **CRITICAL** |
| `OFFICER` | `REGULAR` | `DISMISS_OFFICER` | 임기 만료 또는 보직 해임 의결 | 인사위원회 의결 | AUDIT |
| `REGULAR/OFFICER`| `SUSPENDED` | `SUSPEND_MEMBER` | 산재 요양, 개인 사유 휴직, 징계 처분 | 징계위원회 또는 노사대책부 | AUDIT |
| `SUSPENDED` | `REGULAR` | `REINSTATE_MEMBER` | 요양 종결 진단서, 복직원 제출 | 지부장 확인 + 사무처 승인 | AUDIT |
| `ANY` | `RETIRED` | `RETIRE_MEMBER` | 만 60세 정년 도달 또는 명예퇴직 신청 | 위원장 승인 및 퇴직금 정산 | **CRITICAL** |

## 5. 보안 및 다단계 계층적 RBAC 정책 (Multi-Level RBAC Policy)

### 5.1 RBAC + ABAC (속성 기반 결합) 권한 모델

권한은 고정된 Role뿐만 아니라 속성(Scope, Level, Location)의 교집합으로 결정됩니다.

- **Rule 1 (Downstream Inheritance)**: 상위 계층 관리자는 하위 모든 계층 노드에 대해 읽기/관리 권한을 자동 상속받습니다.
  - 예: 제1항업지부장은 산하 HJNC 연락소, Lashing 1반, Shift A조, 소속 조합원의 데이터를 완전 조회·관리 가능.
- **Rule 2 (Lateral Isolation)**: 동등 레벨 간 교차 접근은 엄격히 차단됩니다.
  - 예: 감만지부장은 신선대지부나 신항 HJNC 연락소의 배차 세부 내역 및 조합원 개인정보를 수정할 수 없음.
- **Rule 3 (Strict Data Masking)**: 주민등록번호 뒷자리, 계좌번호, 건강검진 세부 결과 등 민감 개인정보는 `Lv.1 인사복지부` 전담자 외에는 화면상 `******` 마스킹 처리.

## 6. 타 에이전트와의 데이터 연동 규약 (Inter-Agent Integration Protocol)

```
                       ┌───────────────────────────────┐
                       │   hierarchy-rbac-architect   │
                       └───────┬───────────────┬───────┘
                               │               │
            조합원 자격/소속   │               │ 조직 변경/인사 발령
            가용 인력 풀 쿼리  │               │ 불변 감사 스트림
                               ▼               ▼
           ┌───────────────────────┐       ┌──────────────────────────┐
           │port-dispatch-scheduler│       │governance-audit-guardian │
           └───────────┬───────────┘       └──────────────────────────┘
                       │
                       │ 확정 출역/근로시간
                       ▼
           ┌───────────────────────┐
           │welfare-payroll-fintech│
           └───────────────────────┘
```

### 6.1 `port-dispatch-scheduler` 연동 규약
- **제공 데이터**:
  - `getActiveGangMembers(terminalId, gangId)`: 당일 출역 정지나 휴직 상태가 아닌 유효 조합원 식별자, 보유 특수 자격(신호수, 크레인, 냉동), 직책(반장/조장/조원) 목록 반환.
  - `validateMemberDispatchEligibility(memberId)`: 해당 조합원의 징계 여부, 주간/야간 휴식 보장 여부 즉각 검증 API.
- **수신 데이터**:
  - `onMemberDispatched(memberId, terminalId, vesselId, shift)`: 배차 완료 시 실시간 조직 노드의 `metrics.activeDispatchedToday` 동적 갱신.

### 6.2 `governance-audit-guardian` 연동 규약
- **제공 데이터**:
  - `emitLifecycleEvent(event)`: 승급, 전보, 징계, 퇴직 등 모든 FSM 상태 전이 시 `actorId`, `targetMemberId`, `beforeState`, `afterState`, `timestamp`, `ipAddress`, `cryptographicHash`를 담은 감사 이벤트 발행.
  - 변조 불가능한 감사 로그 블록체인/타임스탬프 원장에 영구 기록.

### 6.3 `welfare-payroll-fintech` 연동 규약
- **제공 데이터**:
  - 조합원 신분(`REGULAR` / `TEMPORARY`), 현행 호봉(근속 연수), 소속 지부 및 직책(`OFFICER_ROLE`) 기준 마스터 데이터 동기화.
  - 직책 수당(반장 수당, 조장 수당) 및 지부별 특수 작업 할증 기준 테이블 제공.

## 7. 엔지니어링 검증 및 가드레일 (Quality & Performance Guardrails)

1. **메모리 풋프린트**: 모바일 기기(저사양 안드로이드 단말기 포함)에서 10,000개 노드 로드 시 클라이언트 힙 메모리 점유율 **35MB 이하** 유지.
2. **반응 속도**:
   - 역할 시뮬레이터 전환 시간: **< 150ms**
   - 조직도 검색 쿼리 응답: **< 30ms**
   - 계층 트리 펼침/접힘 애니메이션: **60fps (무끊김)**
3. **무결성 검증**:
   - 매일 자정 고아 노드(Orphan Node - 부모가 삭제되거나 없는 조합원) 0건 무결성 자동 스캔 실행.
   - 단 하나의 비인가 권한 승격 시도 발생 시 시스템 즉시 격리 및 관리자 긴급 SMS 경보 발송.
