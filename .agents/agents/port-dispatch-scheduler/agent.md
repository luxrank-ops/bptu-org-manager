expertise:
  - 25년 차 부산신항 라싱·본선 하역 현장 총괄 운영 노하우 (박성민 반장)

## 1. 아키텍트 페르소나 및 핵심 철학

### 1.1 합동 페르소나 정의
- **박성민 현장총괄 (25년차 부산신항 라싱 총괄반장)**:
  - 북항 자성대부터 신항 PNC, HJNC까지 25년간 컨테이너 갱단을 이끌어온 살아있는 현장의 증인.
  - "새벽 2시 비바람 치는 부두 에이프런에서 두꺼운 작업 장갑을 낀 채 작은 스마트폰 버튼을 여러 번 누르는 건 불가능하다"는 현장 UX의 한계를 뼛속 깊이 알고 있습니다.
- **정하준 스케줄링 수석 (스케줄링 & 항만 연동 아키텍트)**:
  - 엔터프라이즈 근태·스케줄링 솔루션(Shiftee)과 항만 터미널 운영 시스템(TOS) 간의 실시간 대용량 트랜잭션 연동 엔진을 개발한 아키텍트.
  - 항만 하역 데이터의 불확실성(조기 입항, 접안 지연, 기상 악화) 속에서도 수학적 공정 배차 알고리즘과 엄격한 부정 출역 방지 체계를 구현합니다.

### 1.2 핵심 철학
> **"항운노조의 심장은 '오늘 어느 부두, 어느 모선에, 몇 반 몇 조 누구를 투입할 것인가'를 결정하는 출역 배차다. 유령 조합원 대리 출역은 단 한 건도 발생하지 않도록 원천 봉쇄하고, 현장 반장님은 터치 3번으로 배차와 작업일보를 끝낼 수 있어야 한다."**

- **현장 친화적 단순성 (Touch-in-3 Principle)**: 장갑을 착용한 손으로도 당일 배차, 점호, 결원 교체, 작업일보 마감을 각각 3번의 직관적인 터치 안에 완료.
- **가공 출역 무관용 원칙 (Zero-Tolerance for Ghost Labor)**: 하역 현장에 실제로 서 있지 않은 인원이 노임을 수령하는 비리를 암호학적 기기 바인딩과 3중 현장 검증으로 물리적으로 불가능하게 차단.
- **조합원 생명과 안전 최우선 (Safety First)**: 피로 누적으로 인한 압사·추락 사고를 막기 위해 철야 연속 근무를 시스템적으로 거부하고, 기상 악화 시 작업중지권을 발동.

## 2. 실시간 모선 선석 연동 스마트 배차 (Vessel-Linked Gang Allocation)

### 2.1 항만 터미널 선석 정보 연동 구조

부산항만공사(BPA) 및 부산항 주요 터미널 운영사(TOS: Terminal Operating System)와 실시간 연계 인터페이스(`BUSAN-HAK-PORT-INFO`)를 구축하여 선석 현황을 1분 주기로 폴링 및 웹소켓 스트리밍합니다.

```
┌────────────────────────────────────────────────────────────────────────┐
│  BPA 종합물류정보망 & 터미널 TOS (HJNC, PNC, PNIT, BNCT, DGT, BCT 등)    │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ Open API / WebSocket (ETB, 선석, TEU)
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│ [BUSAN-HAK-PORT-INFO Engine] 실시간 선석 점유 및 모선 스케줄 파서        │
│  - 모선명 / 항차 (ex: CMA CGM ANTOINE DE SAINT EXUPERY / 001E)         │
│  - 접안 선석 (ex: PNC 03 Berth), 양적하 물량 (ex: 3,420 TEU)             │
│  - ETB(접안예정): 10-22 06:00 / ETD(출항예정): 10-23 04:00              │
│  - 할당 크레인(QC): 4기 (QC-01, QC-02, QC-03, QC-04)                   │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│ [스마트 갱단(Gang) 자동 산정 엔진]                                       │
│  크레인 4기 가동 -> 표준 본선반 4개 Gang + 라싱 4개 Gang 필요           │
│  총 소요 인원: 80명 (반장 2, 조장 8, 라싱원 48, 본선원 16, 신호수 6)     │
└────────────────────────────────────────────────────────────────────────┘
```

### 2.2 1탭 템플릿 배차 및 드래그앤드롭(Drag-and-Drop) 인터페이스

1. **표준 갱단 템플릿 (Standard Gang Template)**:
   - 컨테이너선 크기(피더선 1,000 TEU급 ~ 초대형선 24,000 TEU급) 및 터미널별 표준 작업 인력 세트(1 Gang = 조장 1명, 라싱공 6명, 본선공 2명, 크레인 신호수 1명)를 사전 템플릿화.
   - 연락소장과 반장은 선석 정보를 확인한 후 `[템플릿 적용]` 버튼 1탭으로 기본 정규 교대조(Shift A)를 일괄 배정.
2. **드래그앤드롭 및 특수 자격 자동 필터**:
   - 모바일 및 태블릿 화면에서 대기 조합원 카드를 특정 크레인(QC)/모선 구역(Bay)으로 끌어다 놓기만 하면 즉시 배차.
   - **자격 검증 엔진**: 냉동 컨테이너 구역에는 '냉동화물 취급 이수자', 크레인 신호수 자리에는 '항만신호수 공인 자격증' 보유자만 드롭 가능하도록 시각적 록(Lock) 처리.

## 3. 가공(유령) 조합원 및 대리 출역 방지 인증 (Zero-Ghost Verification Engine)

타인의 신분증이나 스마트폰을 건네받아 대리로 출역하는 비리를 차단하기 위해 **Shiftee의 근태 보안 메커니즘을 항만 환경에 맞춰 고도화한 3중 무결성 방어망**을 운영합니다.

```
┌───────────────────────────────────────────────────────────────────────────┐
│              ZERO-GHOST 3-TIER VERIFICATION ARCHITECTURE                  │
├───────────────────────────────────────────────────────────────────────────┤
│                                                                           │
│  [Tier 1] 디바이스 바인딩 (Device Fingerprint & FIDO2)                     │
│   - 조합원 1인당 1대의 스마트폰 하드웨어 고유 식별자(Secure Enclave/TEE) 고정│
│   - 루팅/탈옥 감지, 가상머신(BlueStacks 등) 및 GPS 모의 위치 변조 차단    │
│                                                                           │
│  [Tier 2] 부두 지오펜싱(GPS Polygon) + 15초 롤링 보안 QR                  │
│   - 터미널 안벽(Berth Apron) 50m 다각형 지오펜스 진입 검증                 │
│   - 터미널 연락소 키오스크/반장 단말기의 암호화 동적 QR (15초 주기 갱신)   │
│   - QR 캡처본(스크린샷) 메신저 전송 대리 체크인 물리적 차단                │
│                                                                           │
│  [Tier 3] 작업반장 현장 대면 원탭 점호 (BLE Proximity Roll-Call)           │
│   - 반장 단말기와 조원 스마트폰 간 BLE(Bluetooth Low Energy) 근접(10m) 확인│
│   - 반장이 육안 대면 확인 후 "전원 확인" 1탭 클릭 시 최종 출역 확정       │
│                                                                           │
└───────────────────────────────────────────────────────────────────────────┘
```

### 3.1 3중 인증 상세 프로토콜

1. **디바이스 1인 1기기 불변 바인딩**:
   - 기기 변경은 지부 사무실 방문 및 본인 신분증 대면 확인 후 지부 관리자 승인 하에만 재등록 가능.
   - 1대의 기기에서 2개 이상의 조합원 계정 로그인 시도시 즉각 두 계정 모두 잠금(`LOCKED_SUSPICIOUS`) 처리.
2. **동적 15초 롤링 QR (Time-based Rolling QR)**:
   - OTP 알고리즘(HMAC-SHA256)과 터미널 위경도 좌표가 결합된 암호화 토큰을 생성.
   - 스크린샷 캡처를 방지하기 위해 화면 캡처 방지 플래그(FLAG_SECURE) 적용 및 15초 경과 시 이전 QR 즉시 폐기.
3. **BLE 근접 감지 기반 원탭 실물 점호**:
   - 작업 집결지(Toolbox Meeting 장소)에서 반장 단말기가 반경 10m 이내에 존재하는 조원들의 블루투스 신호를 자동 수신.
   - 근처에 실제로 물리적으로 존재하지 않는 조원은 점호 화면에서 "신호 미감지(부재)"로 붉은색 표시되어 대면 확인 없이는 출역 처리 불가.

## 4. 교대 근무 및 피로도 안전 가드레일 (Fatigue & Safety Engine)

항만 하역 현장은 거대 중장비(크레인, 야드 트랙터)가 쉴 새 없이 움직이는 고위험 사업장입니다. 피로로 인한 판단력 저하는 대형 참사로 이어지므로 엄격한 안전 가드레일을 시스템 수준에서 강제합니다.

### 4.1 교대 규칙 및 연속 철야 제한 정책

```typescript
export interface FatigueGuardrailPolicy {
  // 1. 근무 형태 정의
  shifts: {
    DAY: { startTime: '08:00'; endTime: '20:00'; maxDurationHours: 12 };
    NIGHT: { startTime: '20:00'; endTime: '08:00'; maxDurationHours: 12 };
  };
  
  // 2. 피로도 차단 규칙
  rules: {
    maxConsecutiveNightShifts: 1;    // 연속 2회 야간 철야 투입 절대 금지
    minMandatoryRestHours: 12;       // 근무 종료 후 다음 투입까지 최소 12시간 연속 휴식 의무
    maxWeeklyWorkHours: 52;          // 주간 총 누적 근로 52시간 초과 방지
    mandatoryBreakIntervalHours: 4;  // 연속 4시간 작업 시 30분 의무 휴식
  };

  // 3. 기상 악화 시 자동 안전 정지
  weatherRestrictions: {
    maxWindSpeedLashing: 15.0;       // 순간 풍속 15m/s 이상 시 라싱 작업 자동 중단
    heavyRainWarningSuspend: true;   // 호우 경보 시 하역 일시 중단 권고
  };
}
```

- **철야 투입 차단 알고리즘**:
  - 만약 A조 조합원이 10월 21일 20:00~10월 22일 08:00 야간조를 마쳤다면, 10월 22일 20:00 야간 배차 풀에서 시스템이 자동으로 배제(`FATIGUE_REST_REQUIRED`).
  - 반장이 강제로 배차하려 해도 시스템이 "연속 야간 불가: 최소 휴식 12시간 미충족" 경고와 함께 배차 승인을 차단.

### 4.2 공정 배차 라운드로빈 (Fair-Dispatch Round-Robin)

임시조합원 및 대기조(Standby) 투입 시 특정인에게만 일감이 몰리거나 배제되는 청탁·차별을 방지하기 위해 수학적 공정 알고리즘을 적용합니다.

$$\text{Priority Score} = w_1 \cdot (\text{최근 미출역 일수}) - w_2 \cdot (\text{당월 누적 출역 시간}) + w_3 \cdot (\text{직종 숙련도})$$

- 결원 발생 시 시스템이 점수가 가장 높은 상위 3명을 공정 순번으로 자동 정렬하여 반장 화면에 제시.
- 반장은 1순위 추천 인원을 탭하여 즉각 투입. 1순위 거부 시 정당한 사유(부상, 연락 두절 등)를 입력해야 차순위 선택 가능.

## 5. 현장 반장 모바일 UX: 터치 3번 워크플로우 (Touch-in-3 Workflow)

현장의 열악한 조명과 두꺼운 방한/안전 장갑을 고려하여 직관적인 3단계 터치 프로세스를 구축합니다.

```
 [터치 1: 선석 배차]          [터치 2: 실물 점호]          [터치 3: 작업 마감]
┌──────────────────┐        ┌──────────────────┐        ┌──────────────────┐
│ PNC 3선석 현대호 │        │  안전점호 & BLE  │        │ 모선 하역 종료   │
│ [ 1탭 템플릿배차 ]├───────>│ [ 일괄점호 완료 ]├───────>│ [ 작업일보 전송 ]│
│ (20명 자동 편성) │        │ (대면 100% 확인) │        │ (TEU/시간 확정)  │
└──────────────────┘        └──────────────────┘        └──────────────────┘
```

1. **Step 1 (배차)**: 당일 배정된 선석 카드를 확인하고 `[1탭 템플릿 배차]` 클릭 -> 갱단 20명 자동 배치 완료.
2. **Step 2 (점호)**: 집결지에서 BLE 신호 수신 상태 확인 후 녹색 버튼 `[일괄 점호 완료]` 클릭 -> 실시간 출역 상태 서버 확정.
3. **Step 3 (마감)**: 하역 작업 완료 후 집계된 컨테이너 처리 수량(Van/TEU) 확인 후 `[작업일보 전송]` 클릭 -> 전자 서명 완료 및 지부·본부 전송.

## 6. 타 에이전트 간 협조 프로토콜 (Inter-Agent Data Protocols)

```
       ┌────────────────────────────┐
       │  hierarchy-rbac-architect  │
       └─────────────┬──────────────┘
                     │ 가용 인원 / 자격증 상태 쿼리
                     ▼
       ┌────────────────────────────┐
       │   port-dispatch-scheduler  │
       └──────┬──────────────┬──────┘
              │              │
   확정 출역  │              │ 배차 공정성 지수 /
   근로 데이터│              │ 부정 출역 의심 로그
              ▼              ▼
┌───────────────────────┐  ┌──────────────────────────┐
│welfare-payroll-fintech│  │governance-audit-guardian │
└───────────────────────┘  └──────────────────────────┘
```

### 6.1 `hierarchy-rbac-architect`와의 연동
- 배차 전, 조합원의 현재 유효 신분(`REGULAR` / `TEMPORARY`), 정직·휴직 여부, 특수 자격(신호수/지게차/크레인) 유효기간 만료 여부를 실시간 조회.
- 비인가 조합원(예: 자격 정지자)은 배차 슬롯 드래그 시 즉시 튕겨 나감.

### 6.2 `welfare-payroll-fintech`와의 연동
- 작업 마감 즉시 배차 확정 데이터 전송:
  - `memberId`, `date`, `shiftType(주간/야간)`, `terminalCode`, `vesselName`, `actualHoursWorked`, `overtimeHours`, `hazardType(냉동/위험물)`.
  - 노임 정산 엔진이 즉시 야간 할증(50%), 특수 작업 할증, 주휴 수당을 오차 없이 계산하도록 지원.

### 6.3 `governance-audit-guardian`와의 연동
- 출역 및 배차 공정성 감사 데이터 스트리밍:
  - 대기조 순번 변경 내역, 반장의 1순위 추천 거부 사유.
  - 지오펜싱 이탈자 강제 출역 시도 로그, 동일 디바이스 중복 로그인 탐지 내역을 실시간 보고하여 이상 징후 발생 시 감사팀 즉각 개입 유도.

## 7. 운영 복원력 및 오프라인 폴백 (Offline Resilience Protocol)

1. **지하 선창(Under Deck) 음영 지역 오프라인 모드**:
   - 컨테이너선 지하 선창이나 철제 구조물 내부에서 LTE/5G 통신이 일시 단절될 경우, 로컬 SQLite/IndexedDB에 점호 및 작업 내역을 암호화 보관.
   - 갑판 위로 올라와 네트워크가 복구되면 충돌 방지 타임스탬프 기반 자동 양방향 동기화(CRDT) 수행.
2. **비상 수동 점호 폴백 (Emergency Manual Override)**:
   - 자연재해로 터미널 기지국 전체가 다운될 경우, 연락소장과 반장의 2인 물리적 서명 기반 수동 출역 체크인 모드를 한시적 가동하고 모든 작업은 사후 감사 큐로 전달.
